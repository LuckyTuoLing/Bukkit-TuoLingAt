开发者文档

面向二次开发的说明：项目结构、内部设计、对外 API 与扩展方式。

Java 8 Spigot API 1.12.2 Maven + Shade Lombok

模块职责

包职责不该做的事
command 命令判定、参数校验、调用执行逻辑 不直接拼消息文本，统一走 MessageSender
message MessageGetter 解析、MessageSender 发送 不判断权限、不处理冷却
compat 按版本选择标题 / 音效实现，转换音效名格式 不关心业务，只提供“能用的实现”
listener 事件入口，按配置决定是否注册 不写业务细节，转交 AtExecUtil
cache 进程内状态（在线玩家、冷却） 不发送消息、不依赖插件实例
api / placeholder 对外暴露的稳定契约 改动需考虑兼容性，避免破坏下游

启动流程

主类只做装配，具体工作交给各 Manager：

java 
@Override
public void onEnable() {
    saveDefaultConfig();
    reloadConfig();
    plugin = this;

    registerManagers();     // CompatManager / MessageGetter / MessageSender / CommandManager
    registerCommands();     // at、hanat 的 executor 与补全
    registerListeners();    // PlayerListener 常驻 + ChatAtListener 按配置
    registerPlaceholder();  // 装了 PAPI 才注册，并把加载结果打印到控制台

    ConsoleMessageUtil.printEnable();
}

禁用时清空缓存并打印关闭横幅：

java 
@Override
public void onDisable() {
    PlayerCache.clear();
    CooldownCache.clear();

    ConsoleMessageUtil.printDisable();
}

核心设计

取与发分离

MessageGetter 只负责把配置路径解析成最终文本（占位符替换、颜色转换、可选的 PAPI 解析）， MessageSender 只负责把文本投递到对应通道（聊天 / 标题 / 音效）。 两者通过 ParseMode 表达解析强度：

ParseMode自定义占位符PlaceholderAPI
RAW否否
CUSTOM是否
PAPI否是
CUSTOM_PAPI是是

颜色转换在所有模式下都会执行。当前发送路径统一使用 CUSTOM。

发送顺序与异常隔离

AtExecUtil.at() 会先通知对方、再给自己反馈。 这样即使自身反馈（例如音效）出现异常，也不会导致被艾特的人收不到提醒。

艾特全员走的是 AtExecUtil.atSilent()：只通知对方，不给发起者任何反馈。 否则一次 /at all 会给发起者刷出与在线人数等量的"你艾特了谁"提示。

缓存与线程

  • PlayerCache 用 CopyOnWriteArrayList：写入只发生在进出服，读取发生在任意线程（聊天监听是异步线程），属于读多写少场景。
  • 玩家名匹配用 equalsIgnoreCase，因此 @steve 能命中 Steve。
  • 涉及 Bukkit API 的消息发送、标题、音效，全部通过 runTask 调度回主线程执行。

监听开关

ListenerManager 把“常驻监听”和“可开关监听”分开： PlayerListener 始终注册，ChatAtListener 由配置决定， 关闭时直接注销监听实例，而不是在事件里空转。

跨版本兼容层

标题与音效各由一组实现类提供，每个实现自带 isMatch()： 通过反射探测当前服务端是否具备某个 Bukkit 公开方法，来判断自己是否适用。 CompatManager 按优先级顺序取第一个命中的实现并缓存。

实现判定依据覆盖版本
NowTitleCompat 存在五参 sendTitle 1.11 ~ 26.x
MidTitleCompat 无五参、但有两参 sendTitle 1.8 ~ 1.10
NowSoundCompat 存在字符串版 playSound 1.9 ~ 26.x
OldSoundCompat 不存在字符串版 playSound 1.8

版本分档

标题与音效是两个独立的适配维度，组合出 4 个档位，合起来覆盖 1.8 ~ 26.x。 NowSoundCompat 内部再用 Sound#getKey() 把 1.9+ 细分成两段：

版本区间标题实现音效实现音效名格式
1.8 ~ 1.8.9MidTitleCompatOldSoundCompatSound 枚举值
1.9 ~ 1.10.2MidTitleCompatNowSoundCompat枚举名，如 ENTITY_CAT_AMBIENT
1.11 ~ 1.12.2NowTitleCompatNowSoundCompat枚举名，如 ENTITY_CAT_AMBIENT
1.13 ~ 26.3NowTitleCompatNowSoundCompat资源路径，如 entity.cat.ambient

版本号换规则不影响适配
Mojang 自 2026 年起把版本号改成“年份.序号”，26.3 比 1.21.11 新， 字符串比较会得到错误结论。兼容层全部基于方法存在性探测， 不解析版本号，因此新旧两套命名规则都能自动落档。

音效名归一化

1.9 ~ 1.12 的字符串版 playSound 收的是枚举名，1.13+ 收的是资源路径， 方法签名相同但语义不同。SoundNameUtil 负责两种格式互转：

java 
SoundNameUtil.toResourcePath("ENTITY_CAT_AMBIENT"); // entity.cat.ambient
SoundNameUtil.toEnumName("entity.cat.ambient");      // ENTITY_CAT_AMBIENT

更细的版本差异（该用哪种格式）由 NowSoundCompat 内部探测 Sound#getKey() 是否存在来判定。 发送过程包了 try/catch，解析失败只在控制台告警，不影响其他通道。

为什么不用 NMS
插件只调用 Bukkit 公开 API，不引用任何 net.minecraft / craftbukkit 类， 因此在分支服、混合端上也能加载。

AtEvent 事件

每次艾特真正发出通知前，插件会抛出 AtEvent，供其他插件获取“谁艾特了谁”。 事件在主线程同步触发，可以直接监听。

java 
package com.tuoling.tuolingat.api.event;

public class AtEvent extends Event {

    public Player getSender();      // 发起者；控制台发起时为 null
    public String getSenderName();  // 发起者名；控制台发起时为 "Console"
    public Player getTarget();      // 被艾特的玩家
    public boolean isFromConsole(); // 是否由控制台发起
}

监听示例

java 
import com.tuoling.tuolingat.api.event.AtEvent;
import org.bukkit.entity.Player;
import org.bukkit.event.EventHandler;
import org.bukkit.event.Listener;

public class MyAtListener implements Listener {

    @EventHandler
    public void onAt(AtEvent e) {
        Player target = e.getTarget();
        String who = e.getSenderName();

        if (e.isFromConsole()) {
            // 由控制台发起
        }
        // 例：统计、播报、写入数据库
    }
}
行为约定
事件在消息发送之前触发，当前为不可取消的普通事件（纯通知语义）。 触发时机覆盖指令、聊天框、控制台三条路径。

占位符扩展

插件通过 AtExpansion（identifier 为 tuolingat）向 PlaceholderAPI 注册占位符， 仅当检测到 PlaceholderAPI 存在时才注册。注册结果会打印到控制台：

console 
成功加载依赖: PlaceholderAPI(2.12.3)          # 已安装并注册成功
加载依赖失败(没装PlaceholderAPI，不影响使用)   # 未安装，插件照常运行
占位符返回数据来源
%tuolingat_online%在线玩家数PlayerCache
%tuolingat_player%玩家名请求上下文
%tuolingat_cooldown%剩余冷却秒数CooldownCache

控制台请求（player 为 null）时返回空串或 0，不会抛异常。

扩展点

1. 新增一个子命令

实现 CommandHandler，然后在 CommandManager 构造里注册。

java 
public class AtFooCommand implements CommandHandler {

    @Override
    public boolean isMatch(Command command, CommandSender sender, String[] args) {
        return new CommandUtil(command, sender, args).checkFirstArg("foo", "at", "hanat");
    }

    @Override
    public void execute(Command command, CommandSender sender, String[] args) {
        AtExecUtil.sendHelp(sender);
    }
}
java 
public CommandManager() {
    register(new AtHelpCommand(), new AtReloadCommand(),
            new AtRandomCommand(), new AtAllCommand(), new AtPlayerCommand(),
            new AtFooCommand());   // 新命令加在这里
}
注意保留字
新子命令的名字要同时加进 AtPlayerCommand.isMatch() 的排除列表， 否则 /at foo 会被当成“艾特一个叫 foo 的玩家”。这是当前设计的一个已知耦合点。

2. 注册兼容实现

CompatManager 支持运行时追加 / 移除标题与音效实现，改动后立即按优先级重新选取：

java 
compatManager.registerTitle(new MyTitleCompat());  // 追加（优先级低于已有实现）
compatManager.unregisterTitle(myCompat);           // 移除并重新选取

自定义实现只需实现接口：

java 
public interface TitleCompat {
    void sendTitle(Player player, TitleModel model);
    boolean isMatch();   // 判定当前服务端是否适用
}

3. 监听艾特行为

见上方 AtEvent，这是推荐的对接方式，无需依赖内部类。

构建与部署

依赖

依赖版本scope
spigot-api1.12.2-R0.1-SNAPSHOTprovided
lombok1.18.30provided
placeholderapi2.12.3provided

全部为 provided，不会打进产物，避免与其他插件冲突。

打包

shell 
mvn clean package

构建后 target/ 下会出现两个产物：

文件说明
TuoLingAt-1.0.jar部署用，shade 后的完整产物，放进 plugins/
original-TuoLingAt-1.0.jarshade 前的原始 jar，不要部署
部署后务必整服重启
覆盖 jar 后使用 /reload 或插件管理工具，常常仍会加载旧类， 表现为“改了代码但行为没变”。排查时优先核对报错堆栈里的行号是否与当前源码一致。

编码约定

  • 注释：统一用 // 行注释、简体中文；只在解释“为什么”或版本差异处写注释，不复述代码。
  • 文本颜色：代码内固定文案直接写 § 颜色码，不再使用 ChatColor 常量。
  • 可配置文案：新增给玩家看的提示，优先放进 config.yml 并通过 MessageSender 发送。
  • 版本判断：一律放在 compat 的 isMatch() 里，用反射探测公开 API，不解析版本号字符串。
  • 状态存放：进程内共享状态统一放 cache 包，并考虑读写线程。
  • 命名：类名 UpperCamelCase，方法 / 字段 lowerCamelCase；XxxManager 负责注册与派发。

本地编译校验

没有 Maven 时，可用 javac 全量编译做语法与类型校验（classpath 指向本机 Maven 仓库中的依赖）：

powershell 
$repo = "$env:USERPROFILE\.m2\repository"
$cp = @(
  "$repo\org\spigotmc\spigot-api\1.12.2-R0.1-SNAPSHOT\spigot-api-1.12.2-R0.1-20180712.012057-156.jar",
  "$repo\org\projectlombok\lombok\1.18.30\lombok-1.18.30.jar",
  "$repo\me\clip\placeholderapi\2.12.3\placeholderapi-2.12.3.jar",
  "$repo\com\google\guava\guava\16.0.1\guava-16.0.1.jar"
) -join ";"
$files = Get-ChildItem "src\main\java" -Recurse -Filter *.java | % { $_.FullName }
javac -encoding UTF-8 -cp $cp -d target\classes $files
